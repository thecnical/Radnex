# Security Policy

## 🛡️ Responsible Disclosure

Security and safety are core foundations of **Radnex**. If you discover a vulnerability or potential security risk within Radnex or its runtime dependencies, please notify us responsibly.

**Please do not open public issues for security vulnerabilities.**

Instead, report them via email:
- **Contact:** `thecnical@users.noreply.github.com` (or submit a Private Vulnerability Report via GitHub Advisory)

### What to Include in Your Report:
- A clear description of the vulnerability and potential impact.
- Step-by-step instructions or non-destructive proof-of-concept (PoC).
- Relevant terminal logs, environment details, or stack traces.
- Suggested remediation or patch (if available).

We will acknowledge receipt within 48 hours and work on a coordinated fix and public disclosure timeline.

---

## 🎯 Authorized Scope & Operational Doctrine

Radnex is engineered strictly for **authorized** security assessments, bug bounty programs, educational research, and defensive architecture reviews.

- **Explicit Scope:** Only test domains, URLs, and CIDRs where you have explicit authorization or ownership.
- **Safety Boundaries:** Radnex includes strict out-of-scope enforcement (`out-of-scope.yaml`) and rate-limiting to prevent unintended infrastructure strain.
- **No Malicious Use:** Users are solely responsible for ensuring compliance with applicable computer crime laws and bug bounty terms of service.
